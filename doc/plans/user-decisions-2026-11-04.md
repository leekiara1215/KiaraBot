# 用户决策注册（2026-11-04）：新增五项工作范围

## 1. 来源与授权

用户在当前对话明确要求：

> 除了第一项，后续5项纳入计划，然后你负责统筹管理，具体任务交给subagent处理

“第一项”指上一轮逐项说明中的“两主机部署与断网演练”；“后续五项”按原顺序为：

1. 目标 Control WebSocket；
2. 模型 streaming；
3. 未知 Host 请求的错误语义对齐；
4. 独立 host operation 管理；
5. `bootstrap_credential` 的安全交付与字段级验收。

这次授权把五项从延期或保留缺口转为正式计划范围，不代表已经实现或验收。
旧记录中“仅文档化、不扩契约”“streaming 明确不做”“P12 v1 无目标 WS”的范围限制，
在上述五项的新实施计划中由本决定替代；旧执行记录保留原日期和证据作用域。
现有运行能力与 `not_implemented` 状态，仍须在真实实现和对应验收完成后才能更新。

## 2. 仍然延期的范围

两主机部署与断网/网络分区演练继续延期，本次不追加这项交付门槛。
WS 重连、模型流中断、凭据交付响应丢失等属于各新增能力自身的必要故障测试，
不因此扩展为两主机或独立断网演练项目。自动跨主机接管、高可用不在本决定内。

## 3. 组织与执行

- 主代理负责拆分依赖、冻结跨模块接口、协调文件所有权、集成评审、验证与交付状态。
- 具体工作交由 subagent。
- 首批分为 Control WS、模型 streaming、Host/Bootstrap 三个工作流；Host/Bootstrap 内仍分别跟踪三个独立范围。
- 先形成可审查的任务与契约方案，再按“契约/接口 → 各模块实现 → 集成与验收”推进。
- 各工作流不得自行扩大公共权限、共享契约或数据库责任；冲突由主代理协调。
- 当前工作区已有未提交重构，须保留，不将其并入新增功能的完成证据或擅自提交。

本登记没有授权真实 QQ 主动发消息、付费 Provider 调用、修改运行环境或正式发布；
这些动作沿用各自已有授权和验收范围。新增功能可先用本地真实 HTTP/TLS/进程夹具验证。
