## 2. 现有实现对拆分的约束

- 当前 [组合根](../core/app/main.cpp) 装配 AdapterIngress、PluginHub、ActionRouter、HostDispatcher、TaskScheduler、ControlService 和模型 Provider，不能直接按类生成同等数量的服务。
- [Core 文档](02-core.md) 和 [入口实现](../core/src/application/adapter_ingress.cpp) 的事件、顺序水位和逐插件投递具有原子提交关系。建议保留在同一运行时事务边界内，避免再拆独立事件接入服务与投递账本服务。
- 当前任务触发由 [TaskScheduler](../core/src/application/task_scheduler.cpp) 与 inbox 同事务提交。拆分调度后该单事务保证不能原样延续，须重新设计持久交接、去重和完成定义；COMPLETED 当前表示事件已入队，不能悄悄变成仅发送一次请求。
- [模型调用](../core/src/application/host_dispatcher.cpp) 已区分调用前后审计与外部调用，不承诺外部原子性或自动重试。远程化不能将超时解释为未计费。
- [现有服务契约](../proto/kiarabot/v1/services.proto) 只有 AdapterBridge/PluginBridge 双向流；下述管理、身份、宿主、调度及模型内部契约尚未定义，不能标为现成 RPC。
- [基础设施文档](05-infrastructure.md) 中部分端口未接线，FileStorage 无生产消费方；不将其拆成无用例的远程存储服务。

## 3. DD01：服务清单与职责粒度

### 3.1 确认结论

2026-11-01，用户确认 DD01=B：按主要能力划分控制管理、身份与访问、Core 运行时、插件宿主、任务调度、模型网关六类平台服务。职责划分见下表；数据和契约细则不据此自动批准。

六类平台服务不含每个渠道适配器实例、插件业务进程，也不包括数据库、反代、日志系统和一次性迁移命令。六类不表示运行六个副本或承诺高可用。

### 3.2 已确认的服务职责

名称是逻辑暂名，不冻结二进制名称、仓库目录或端口号。

| 服务 | 逻辑归属 | 输入与职责 | 输出与边界 |
| --- | --- | --- | --- |
| 控制管理 Control | 控制 API | 接收浏览器 REST/WS，校验请求形状，聚合查询，将管理操作交给业务所有者 | 浏览器响应、操作状态和获授权状态流；不直接修改其他服务业务表，不作最终 Action 授权 |
| 身份与访问 Identity | Core 身份/授权能力 | 人类会话验证与撤销、服务及业务实例身份、固定角色与资源授权、可信身份上下文 | 身份验证与授权依据、撤销/版本信息；不决定群动作预算或业务可执行状态 |
| Core 运行时 Runtime | Core 事件/插件/Action 能力 | 适配器/插件协议入口，账号绑定和注册的业务校验，事件排序及目标选择，插件期望状态/配置，投递尝试/续租/ACK，Action 授权与配额、插件命名空间 | 持久事件确认、投递、Action 受理/结果、配置与状态；不启动远程 OS 进程，不执行平台私有 API，不直接调用模型供应商 |
| 插件宿主 Plugin Host | Core 运行支撑 | 接收获授权的运行期望，在本机受控启动/停止插件进程，观测退出和应用结果 | 插件进程实际状态、运行代次与执行回执；不自行授予权限，不拥有投递 ACK 账本 |
| 任务调度 Scheduler | Core 任务能力 | 创建/查询/取消任务、到期领取、触发交接及恢复 | 向 Runtime 交接 TimerTriggered，报告任务状态；不直接调用插件或适配器 |
| 模型网关 Model | Core 模型应用能力 + infrastructure Provider | 接收受权模型调用，模型配置与密钥更新，供应商调用、超时、并发限制和调用审计 | 模型结果或明确失败/未知结果；密钥不交给插件，不自动重试可能已计费调用，不拥有会话历史 |

表中细分数据的唯一权威已按 DD02.1=B 确认；数据库隔离、缓存/投影时效及凭据实现细节继续评审。Identity 不预先承诺完整用户管理或自定义角色；Model 不扩展流式、工具调用等未批准能力。

拆分不改变逻辑模块责任：Identity、Runtime、Scheduler 仍属于 Core 业务能力；Plugin Host 属 Core 运行支撑；模型业务授权/配置生命周期与供应商 HTTP 实现分层，具体 Provider 仍属基础设施。进程独立不意味着把业务规则交给基础设施。

### 3.3 外围进程与不新增的服务

| 进程/组件 | 定位 |
| --- | --- |
| 渠道适配器实例 | 独立进程，可部署在平台连接所在主机；通过统一协议连接 Runtime，保留平台本地映射和副作用去重 |
| 插件业务实例 | 独立进程，通过 SDK 与 Runtime 交互；受管实例由所在主机的 Plugin Host 管理 |
| 外部自管插件 | 可直接按获准身份注册 Runtime，不要求伪装为宿主管理；其启停能力须明确区分 |
| 面板、反代 | 静态前端和访问入口，不持有业务数据权威 |
| 数据库、日志与监控 | 中央 PostgreSQL、边缘 SQLite；业务私有库，日志/监控基础设施不拥有业务规则 |
| 迁移命令 | 一次性运维任务，按 A05 显式执行，不算常驻业务服务 |
| 远程文件/通用数据库服务 | 本轮不新增；无文件用例，Repository 也不等于远程数据库 RPC |
| 独立审计汇聚服务 | 首轮不设为业务成功的必经远程提交点；各所有者先保证必要审计可靠性，集中查询经各所有者授权接口聚合 |

### 3.4 四条关键业务链路（仅用于评审边界）

1. 平台事件：Adapter → Runtime 原子保存事件、会话水位、目标投递 → 已注册插件经 SDK 处理 → ACK/续租回 Runtime。Plugin Host 不夹在每条业务事件路径中。
2. 管理插件：Control → Runtime 接受期望状态/配置 → Plugin Host 执行进程动作并报告实际状态；插件配置应用按插件 ACK 记录。持久化接受、进程启动、插件配置生效三者不能合并成一次成功。
3. 任务触发：Scheduler 持久化一次触发意图 → 交接 Runtime → Runtime 持久化去重与事件入队 → Scheduler 记录交接确认。具体 outbox/inbox 或其他可靠机制、取消竞态与完成语义在 DD03/DD04 决定，不能只发一次 RPC。
4. 模型请求：插件经 SDK 进入 Runtime → 身份/业务门禁 → Model 网关及其独立权限验证 → Provider。可信委托上下文和撤销传播在 DD03 明确；超时保留可能已经调用/计费的语义，不能盲目自动重发。

上述逻辑链路的模式已由 DD03 确定，具体方法与参数见通信设计：高风险在线授权、普通只读有限缓存，首轮不使用 broker，不默认离线放行。

### 3.5 主要取舍与故障边界

- 事件入库、目标插件快照、投递账本留在 Runtime，优先守住一条本地事务；Action 记录与预算也同属 Runtime，避免另拆一个配额服务参与受理事务。
- Runtime 仍有多个内部应用模块，不把本次六类服务当作禁止进一步模块化的理由；如果实际负载或组织边界要求进一步拆分，单独提出证据与协议调整。
- Plugin Host 管理本机进程，不向 Core 提供任意 shell/路径执行能力；部署、插件包分发及允许的启动配置在详细契约中约束，不据本项新增自动分发系统。
- Identity 不可用不能自动视为有权限；短期签名证明和风险分级上界见 DD03.2–DD03.3。多个服务验证身份与执行本地业务授权不等于多个服务各建一份权威授权表。
- Scheduler 与 Runtime 断网时需要保留待交接意图并可恢复；不能报告插件已执行。具体容量、过期与背压行为待协议评审。
- Model 故障隔离外部慢调用；Control 故障不应停止已获准的运行链路，但新管理/登录会不可用；身份撤销按 DD03.3 及通信设计执行。
- 所有服务须能跨主机运行，但本项不指定 Kubernetes、注册中心、数据库产品、多副本写入或高可用。

## 4. DD02.1：数据唯一权威与访问规则（已确认 B）

### 4.1 本项边界

本项决定谁有权接受一类数据的变更、谁保存权威事实、其他服务如何读取。数据库产品、一个或多个数据库实例、schema/账户隔离、表字段、缓存期限和跨服务事务机制不在本项决定。

单一所有者指同一业务事实仅有一个权威服务，不等于只允许一个进程副本，也不保证多副本并发写安全；副本写入规则须另作设计。

### 4.2 确认结论

2026-11-01，用户确认 DD02.1=B：业务所有者保存唯一权威数据，Control 通过协议提交命令、聚合查询，只拥有控制技术状态。其他服务的读投影不具业务写入权，不直接跨服务读写表。

物理共用数据库集群不等于共享写表；物理隔离、引擎与授权缓存规则分别按后续已定稿章节执行。

### 4.3 已确认的权威数据清单

| 数据 | 唯一权威或来源 | 其他服务可持有什么 |
| --- | --- | --- |
| 人类身份、密码验证材料、登录会话、刷新/撤销状态 | Identity | 经过验证的身份上下文和有界缓存，不复制一套可写会话库 |
| 服务/业务实例身份登记、凭据验证材料、固定角色分配、资源授权、撤销版本 | Identity | 业务执行所需授权依据，失效与撤销传播在 DD03 明确 |
| 机器人账号目录、适配器绑定与获准注册元数据、有效连接代次 | Runtime | Control 读投影；Adapter 平台本地事实；身份登记引用同一资源 ID |
| 插件安装/逻辑实例、清单、订阅、启用期望、期望配置及版本 | Runtime | Host 的执行目标副本、插件接收的获准配置、Control 读投影 |
| 本机受管进程的执行日志、启动代次、退出观察 | Plugin Host | Runtime 保存报告及其版本/时效；离线报告不是进程仍存活的证明 |
| 插件协议注册、配置应用 ACK、投递状态与尝试/租约/ACK/死信 | Runtime | Host 不另设有裁决力的 ACK 账本；Control 只读授权投影 |
| 事件 inbox、会话顺序水位、投递目标快照 | Runtime | Adapter 保留待确认上报与平台顺序日志，不修改 Runtime 表 |
| Action、幂等、取消/结果、危险动作策略、预算、暂停状态 | Runtime | Adapter 本地执行去重与平台结果，Control 汇总状态 |
| 插件命名空间数据与 Host 存储收据 | Runtime | 插件经 SDK 访问；逻辑 namespace 的业务归属仍为插件，不因托管改变所有权 |
| 任务定义、领取、触发意图、取消、交接记录 | Scheduler | Runtime 保存已接收触发及投递状态，两者是不同事实 |
| 模型别名、端点配置、密钥引用/密文、调用意图与已知结果 | Model | Control 只读脱敏元数据并提交更新；Runtime/插件不持有供应商密钥 |
| 业务成功幂等收据、必要业务审计 | 执行业务的各服务本地拥有 | Control/观测系统可以汇聚，但汇聚副本不作为业务提交成功的唯一证明 |
| UI 聚合、可重建缓存及流游标等控制技术状态 | Control（如需要） | 不变成其他服务业务配置或授权的权威 |

### 4.4 必须分清的相似事实

1. Identity 登记身份和授予操作范围；Runtime 保存账号绑定、插件清单和业务启用策略。有效权限受获授范围与业务门禁共同约束，不接受清单自报授予。
2. 插件期望启用、宿主进程已启动、插件协议已注册、配置已应用、投递已 ACK 是不同事实，分别有来源和版本，不能用一列 running 混合表示。
3. Runtime 保存 Action 请求与接收结果；Adapter 保存平台实际调用及去重日志。跨网断线时允许结果未知，不能由一侧覆盖另一侧的已知事实。
4. Scheduler 保存定时触发意图与交接确认；Runtime 保存事件是否已经持久接受。任务触发接受不等于插件已执行，具体完成语义在 DD03/DD04 定义。
5. Identity 维护注册/验证与撤销材料，不因此集中保存所有服务的明文私钥；各进程私钥或秘密引用由部署机制供给。CA、签发、轮换及密钥库产品另行评审。
6. 模型供应商密钥属于 Model 使用范围；平台登录材料留在 Adapter/外部平台相应边界。插件配置若含秘密，投递范围与秘密引用须另行设计，不默认明文复制到所有服务。

### 4.5 已确认的读写与删除原则

- 管理命令通过协议交给权威服务校验、提交、记录版本；Control 不先保存另一份有权威性的业务配置再逐服务覆盖。
- 其他服务通过所有者查询接口或版本化投影读取；不得直接跨服务读写业务表。统计汇聚不能伪装成一个跨服务原子快照，陈旧/不可用状态须可表达。
- 投影不能用作无上界授权缓存；缓存有效性、权限撤销上界、不可验证时的拒绝行为在 DD03 确认。
- 每个执行方的收据与必要审计随本地业务事务提交；全链路操作进度可聚合，不能代替执行方收据。具体事务原子组留待 DD04。
- 资源删除/停用不能跨库级联直接删除其他服务数据；引用、墓碑、保留和交接清理规则后续具体定义。
- 多插件实例下，命名空间按逻辑安装共享还是逐实例隔离需独立确认，本项仅确定托管服务；身份/实例/安装 ID 不在这里合并。

### 4.6 确认范围

DD02.1=B 已确认，包含上表归属及读写原则。物理数据库、命名空间和授权时效按后续已定稿章节执行；表字段作为实施规格落地。

## 5. DD02.2：数据库隔离与部署（已确认 B）

### 5.2 已确认的存储布局

| 服务或组件 | 持久化建议 | 边界 |
| --- | --- | --- |
| Identity | 独立身份逻辑库 | 身份、会话、授权、撤销及本地审计/收据 |
| Runtime | 独立运行时逻辑库 | 账号、插件、事件、投递、Action、配额和命名空间等关系表及原子组 |
| Scheduler | 独立调度逻辑库 | 任务、触发与交接记录及本地审计/收据 |
| Model | 独立模型逻辑库 | 模型配置、密钥引用/密文、调用记录及本地审计/收据；加密主密钥不得与密文同表保存 |
| Control | 不强制建库；确有可靠性需求时用自有技术库/缓存 | 可重建聚合、游标与控制技术状态，不重建业务权威 |
| Plugin Host | 每主机/宿主隔离的持久执行日志 | 便于进程恢复，不能冒充 Runtime 的业务/ACK 账本；SQLite 本地日志，按宿主/实例隔离 |
| Adapter | 保留实例隔离的本地上报/平台执行日志 | 不迁入 Runtime 共享写库，不因中央库存在就取消平台副作用去重 |
| 插件业务实例 | 通过 SDK 访问 Runtime 托管命名空间 | 不发放平台数据库账户，不能直接连库 |

并非六类服务必须各部署一个数据库集群；四个主要业务逻辑库可先共享数据库部署。Host/Adapter 的本地事实记录不等于第二套中央业务权威。

### 5.3 已确认的访问、迁移与故障原则

- 服务运行账户只具有本服务所需数据权限，不具有其他服务库访问权，不使用超级用户或跨库授权绕过 RPC。
- 显式迁移使用独立部署身份，权限局限于对应库；常驻服务默认不持有建表/升级权限，按 A05 验证版本后启动。
- 外部资源 ID 是逻辑引用，不使用跨服务数据库外键、跨库视图/联表或共享存储过程实现业务耦合；引用有效性及删除协调通过契约设计。
- 不使用跨服务数据库事务作为日常业务原子性方案；本地业务表、收据、必要审计及待交接记录在本服务库内组合，具体 DD04 确认。
- 共用物理集群仍会共同受数据库故障、连接压力、存储耗尽影响，需要连接预算、容量与告警；不据逻辑隔离承诺高可用。
- 各逻辑库有独立版本与迁移记录，但分布式升级仍需兼容顺序。备份与恢复按业务依赖协调，不宣称同一集群就自动获得应用一致快照，也不能随意只回滚一库。
- 业务服务跨主机通过数据库网络连接私有逻辑库，不通过共享本地 SQLite 文件实现跨主机事务。具体数据库引擎和网络认证仍须单独评审。

### 5.4 确认范围

DD02.2=B 已确认：服务专有逻辑数据库、独立运行/迁移身份，首期允许共用物理数据库部署，Host/Adapter 保留实例隔离日志，Control 不为凑齐数量强制建库。产品、版本、备份参数、HA 和具体表结构不在本项批准。

## 8. DD02.5：插件存储命名空间隔离（已确认 C）

### 8.1 当前约束

当前 host.storage.v1 由认证插件身份派生命名空间，不接受插件自报 namespace；存储写入、幂等收据与审计同事务。已有每插件容量、键数、TTL 与收据上限。目标从空安装/实例建立命名空间，不复制旧 plugin_id 数据；身份派生与原子存储原则继续保留。

以下讨论 Runtime 托管的插件业务数据，不是插件配置、任务/Action 所有权或平台执行日志。那些状态由各自业务契约确定，不能因共享存储就自动共享操作权限或任务所有权。

### 8.2 确认结论

2026-11-01，用户确认 DD02.5=C：默认实例私有 namespace，安装内共享空间须由获授权管理者显式开启并配置成员及读写范围；不支持按插件类型跨安装默认共享，也不据此批准任意跨安装共享。

共享存储不自动共享任务、Action、账号操作权限或其他实例私有数据；详细接口、并发控制和限额数值继续评审。

### 8.3 已确认的具体边界

- 默认 SDK storage 操作访问由已认证稳定 plugin_instance_id 派生的私有 namespace，不接受自报 owner/namespace。执行或连接代次变化不更换 namespace。
- 同一安装内如有共享需求，由获授权管理者显式开启并配置成员及读/写范围；不能仅凭相同 plugin_type_id、installation_id 的自报值获得访问。
- 共享访问通过服务端验证的作用域/句柄或单独 SDK 上下文表达；线协议字段、特性名及权限词表在 DD03 确认，不在本文直接创建稳定码或 capability。
- Identity 的资源授权与 Runtime 的安装成员/共享启用状态共同约束访问。关闭共享或撤销成员后的缓存失效、在途请求处理须写入契约，不默认已经打开的连接永久有效。
- 私有空间仍可保存实例本地逻辑状态；共享空间仅保存明确需要协作的业务状态。共享并不意味着任意实例获得其他成员私有空间访问权。
- 共享写入必须明确版本冲突或条件更新等并发语义；只读再写不是可靠分布式锁。具体原子操作是否增加在 DD03/DD04 另行确认，不能据共享 namespace 承诺副作用只执行一次。
- 存储幂等记录绑定认证调用方、有效 namespace 及操作作用域；不得让不同实例的相同键意外重放彼此响应，不能用共享模式绕过授权。scope 与原子组见通信/事务设计，无旧数据迁移。
- 限额区分实例、共享空间及安装聚合，避免通过增加实例无限放大存储额度；数值、TTL 和收据上限已在事务设计定稿，只在统一目标实现中生效。
- 升级/重启/迁移宿主保留稳定实例的数据；新增实例默认空私有空间。删除实例/安装时按后续生命周期规则保留或清理，不立即隐式级联删除共享数据。
- 不导入或复制旧 namespace；新系统内保留的控制/审计状态不能以插件 namespace 暴露。

DD02.5=C 已确认，将受控安装内共享能力纳入后续接口设计；CAS、限额和 SDK 作用域按通信/事务设计；没有旧 namespace 映射，实施时统一重建 Host 契约。

### 9.1 确认结论

### 9.2 已确认的阶段与权威

- 停用是可逆业务开关：所属服务提交本地禁止新操作的状态，不隐式删除配置或数据；是否暂停已有任务、取消待派发 Action 在业务契约中定义。
- 删除受理后进入逻辑删除/处理中状态，保留资源 ID 和必要墓碑；面板区分受理与跨服务清理完成。状态名与错误码在契约设计中定义，不在本文件创造新稳定枚举。
- 删除由资源所有者驱动，其他服务完成自己权威数据的本地变更及回执；Control 展示进度，不跨库级联。Identity 的授权/凭据撤销与 Runtime/Scheduler/Model 的业务禁用是不同步骤。
- 本地业务禁用提交后，该所有者拒绝相应新操作；跨服务撤权与缓存失效有明确收敛上界，DD03 再定。不能承诺管理点击后全系统瞬时撤销，也不能离线无限放行。
- 已经发生的平台副作用不能撤销；未知执行结果保留恢复依据，不能以删除记录来伪装动作未执行。模型在途请求亦不因删除而保证未计费。
- 不回收资源 ID 给其他资源。仅保留最小墓碑，不要求永久保留全部业务内容；物理清理、备份过期及密钥销毁需分别说明，主库删除不等于备份同时消失。

### 9.3 已确认的分类处理原则

| 对象 | 删除/停用处理 |
| --- | --- |
| 插件实例 | 禁止新投递与 Host 能力使用，撤销对应访问并停止受管进程；留状态报告/恢复证据，私有 namespace 按清理策略处理；外部自管进程不能谎报已物理停止 |
| 安装内共享空间 | 删除一个成员只撤销成员访问，不删除其他成员共享数据；删除整个安装再处理共享空间 |
| 机器人账号/适配器绑定 | 先禁止新出站与相应注册/路由，协调断线和未决动作；保留历史事件、动作和必要去重记录至条件满足 |
| 定时任务 | 区分取消与删除；已触发交接不能通过删任务“撤回”，后续事件处理按 Runtime 目标状态和取消竞态契约决定 |
| 模型配置/密钥 | 停止新调用，撤销或轮换凭据；密文与秘密引用保留应尽量少，秘密销毁不受普通业务内容恢复窗口默认约束 |
| 人类会话/凭据 | 撤销不能依赖日后清理行才生效，恢复业务资源不自动恢复旧 token 或凭据 |
| 收据、必要审计、投递与平台去重 | 不随资源逻辑删除一并清空，遵守原有各作用域期限和未决恢复需要 |

### 9.4 保留、恢复与清理边界

- 配置及插件数据的恢复窗口、墓碑保留和清理任务间隔须单独给出数值，不在本项任意设成全局统一期限；已过期的 namespace TTL 不因软删除自动续期。
- 内部成功命令至少七天、Control/Host 各自既有收据期限保持；具体记录须满足仍有效的幂等/投递恢复义务后才能清理。长期未知结果需定义处置与脱敏方案，不以“待恢复”为由无期限保存全部内容。
- 允许恢复的资源需在窗口内重新校验权限、绑定和依赖；不自动恢复已撤销凭据、已取消任务或过期租约。永久删除后再次创建是新资源 ID。
- 清理失败、依赖离线和重复删除应有可查询进度与幂等处理，不报告全部完成；删除与恢复并发、成员删除与共享空间清理的原子判定在 DD04 明确。
- 历史投影/备份不得把已删除资源重新激活；恢复演练需处理墓碑、凭据撤销与跨库版本一致性。

### 10.3 持久交接的最低边界

- 发送方在本服务事务里提交业务状态、必要收据/审计及 outbox；不在未提交时执行远程副作用，不持有数据库事务等待网络。
- 派发工作者使用稳定消息/命令身份发送；接收方将去重、业务变更及必要审计在自己本地事务提交，再返回持久确认。发送方据确认更新派发进度；确认丢失时允许重发同一身份。
- 接收确认不等于后续插件、平台或下游全链路完成；一个操作可有多个阶段结果，必须可查询并关联 request_id/trace_id/operation 身份，具体字段 DD03 后续定义。
- 重试仅针对可恢复、具备幂等语义的交接；鉴权拒绝、输入错误不无限重试。对执行结果未知的外部副作用不得套用通用自动重发策略。
- 队列容量、退避、超时、死信、过期、取消与有序范围须明确；满载不静默丢弃已经承诺受理的工作，持续异常须可观测/处置。
- 不跨服务直接查询/修改他人的 outbox/inbox；数据库不成为共享事件总线。dispatcher、接收去重表和具体锁策略在 DD04 落定。
- 调用上下文身份、服务鉴权/加密及授权撤销机制在 DD03.2 等后续项决定，本项不因网络可达就默认可信，也不选择具体证书体系。

### 10.4 目标契约范围

服务间命令、查询与事件继续以 proto 为唯一来源；REST/WS 仍为 OpenAPI/AsyncAPI。现有仅有 AdapterBridge/PluginBridge 不能视为新管理 RPC 已存在。

### 11.3 已确认的信任链

## 12. DD03.3：权限撤销时效与 Identity 故障（已确认 C）

### 12.1 不得悄悄放宽的现行承诺

跨服务授权检查与本地提交不构成全局原子撤销；即使逐请求在线校验，已在途操作也需明确检查点。已发生平台副作用不能通过撤权撤销。

### 12.2 确认结论

2026-11-01，用户确认 DD03.3=C：按操作分级，高风险与敏感操作在线获取当前权威授权；明确列出的普通只读可在有效证明和缓存窗口内继续。按本次建议记录内部证明与普通只读授权缓存至多 60 秒，两者取更早失效；收到撤销信息立即失效。

### 12.3 已确认的分级与时效

- 高风险至少包括：账号/凭据/密钥及授权配置修改、插件启停与共享成员变更、资源删除/恢复、平台出站 Action、可能计费的模型调用、敏感数据读取。最终业务执行方在新操作的授权检查点向 Identity 获取当前权威判断，不能靠未过期证明单独放行。
- 普通只读仅限契约明确标记的非敏感状态/健康/脱敏元数据；默认、未分类或权限不明确的方法按高风险处理，不自行降级。
- 内部调用证明有效期至多 60 秒，普通只读授权依据的新鲜度也至多 60 秒；两者取更早失效。收到可靠撤销/版本失效信息立即失效，不等窗口耗尽。总放行目标上限包含时钟容差，不能在 60 秒之外再无限叠加宽限。
- 浏览器 REST 每次验证权威会话状态；Identity 无法确认时拒绝，不返回成功的缓存结果。WS 至少按既有一秒要求检查会话有效性，无法确认时在该上限内关闭。业务授权变化可按更严格检查点处理，具体映射 DD03 方法设计明确。
- 有效缓存必须来自已校验的权威状态；读取本地缓存、重新连接或收到普通请求不能刷新新鲜度。服务重启不得把落盘旧缓存当作新验证。
- 不签发/续发未知授权；未知签名键、证书/证明过期、接收方不符、时钟不可可靠判断均拒绝，不退化明文或无限离线权限。证书撤销和信任根更新机制需另行设计，不能声称短 token 自动解决已建立 TLS 连接的证书撤销。

60 秒已按本次建议获确认，尚非当前实现行为；具体时间源、同步假设、误差上界及校验方式在实现规格中定义和测试。

### 12.4 依赖故障与已受理工作

- Identity 故障不伪装成“权限不足”或“资源不存在”；授权不可确认与明确拒绝应按契约区分，不在本文直接新造错误码。
- 接口收到明确拒绝后不自动重试；依赖不可用的可恢复工作保留进度，按受控退避恢复，不静默丢弃或越权执行。
- 用户会话自然过期不自动取消已经持久接受的定时任务或配置操作；执行时以获准服务身份及记录的执行策略继续，不反复保存/复用原用户 token。
- 明确撤销业务权限、停用资源或删除应影响后续执行检查；高风险待执行工作需要新鲜授权，无法确认则暂停，不能只凭过去受理时的证明强行执行。
- 已发生的外部调用或已派发动作不承诺回滚；已受理操作的取消、暂停、失败终态及恢复按 DD04 用例定义。新的高风险操作与已有安全收尾/审计、记录既有平台结果须区分，不能因鉴权依赖故障丢失已发生事实。
- 需要在线授权且暂不可确认的工作，在未确认前不调用平台/模型；具体授权检查与副作用间的可接受竞态、授权版本及运行代次隔离在 DD04 明确。

## 14. DD03.5：Identity 服务方法与授权职责（授权助手采用 B）

### 14.1 定稿结论

用户授权后续决策由助手决定，助手采用 B：会话、主体登记、凭据生命周期、受限委托、当前授权与失效同步形成闭环。不扩展完整用户管理、自定义角色、联合登录或外部 IAM 平台。

以下是目标逻辑方法名，不是已新增 RPC；统一契约落地前须定义请求/响应和权限词条。最终定稿方法与参数见 [通信设计](21-service-contract-design.md)。

### 14.2 人类会话方法

| 操作 | 调用方/授权 | 输入要点 | 输出/持久语义 |
| --- | --- | --- | --- |
| Login | Control 代表未登录用户；限频且审计，不能要求已有用户会话 | 受保护传输中的用户名/密码、请求上下文与登录作用域幂等键 | 提交会话/收据后返回 token 对；沿用现行期限、加密重放和敏感信息规则 |
| RefreshSession | Control 携带有效刷新凭据 | refresh token、幂等键 | 同 session_id 轮换，旧 token 规则及同键重放按既有契约，不扩展为无限续期 |
| ValidateSession / GetPrincipal | Control 每次 REST/WS 验证入口 | 现行 bearer/会话凭据与上下文 | 当前权威主体、会话、有效固定角色/资源依据；失效返回明确错误，不用旧缓存伪装成功 |
| ListSessions | 本人范围或现行管理员权限 | 分页和可信调用上下文 | 授权范围内会话；不得返回 token/hash/密钥；维持现行分页和不可见规则 |
| RevokeSession | 本人或管理员获准范围，Identity 本地校验 | session_id、幂等键 | 本地撤销、审计/收据及失效交接原子提交；远端关闭不能假装同事务完成，REST/WS 既有上界仍需兑现 |

浏览器 token 15 分钟/30 天等现行契约不因内部证明 60 秒而改变。完整用户创建/删除、密码重置和自定义角色管理不由此自动进入范围。

### 14.3 平台及业务实例身份

| 操作 | 调用方/授权 | 输入要点 | 输出/边界 |
| --- | --- | --- | --- |
| RegisterPrincipal | 获准管理者经 Control 或受控部署入口 | 主体类型、关联资源 ID、允许服务/实例绑定，禁止自助任意注册 | 稳定主体及验证材料引用/登记版本；不把资源 ID 当作凭据 |
| RotateCredential / RevokeCredential | 有对应身份管理权限的调用方 | credential 引用、预期版本、幂等键 | 更新凭据状态、版本和失效意图；轮换期间有效范围具体定义，不返回已有秘密明文 |
| GetPrincipalStatus | 获准平台服务或管理者 | 主体/凭据引用 | 可供校验的状态/版本，不返回密码验证材料、私钥或完整 token |

平台证书首次引导、CA 签发和私钥交付不是 RegisterPrincipal 自动承担的职责，部署信任根和轮换细节另行设计。Plugin Host 仅可在已授权目标范围内请求绑定，不允许以宿主身份为任意插件授予权限。

### 14.4 委托、授权与失效

| 操作 | 调用方/授权 | 输入要点 | 输出/持久语义 |
| --- | --- | --- | --- |
| IssueDelegation / ExchangeDelegation | 已认证且获准委托的 Control/Runtime 等服务 | 被验证主体、目标 audience、操作/资源子集、父委托及上下文 | 至多 60 秒受限证明，绑定调用服务，不能增权；签发失败不得降级成信任正文 |
| CheckAuthorization | 最终业务执行服务；Identity 管理自身写入时直接使用本地权威规则 | 主体、委托、方法、资源及授权依据版本 | 当前允许/拒绝及判断版本/时效，不能用副本滞后伪装当前权威；依赖错误与明确拒绝分开 |
| ListAssignments | 获准管理者，或主体/服务获准自查范围 | 主体、资源、分页 | 固定角色分配与资源授予的可见投影，不扩展自定义权限词表 |
| SetAssignment / RevokeAssignment | 获准身份管理者，禁止客户端自报管理员角色 | 主体、固定角色或已登记操作范围、资源、预期版本、幂等键 | 版本、授权变更、审计/收据及失效交接同本地事务；幂等重放仍校验当前权限 |
| WatchInvalidations | mTLS 认证且获准的服务，限制订阅范围 | 持久游标/授权范围 | 带顺序/版本的失效通知；断流与游标过期不能当成永不撤销 |
| GetAuthorizationSnapshot | 同上 | 所需主体/资源范围与版本 | 权威版本和快照，用于断流补齐；不传播所有用户和凭据的全量秘密 |
| GetVerificationKeys | 受控服务引导/轮换入口 | 已建立信任的调用上下文、所需键版本 | 公开验签材料及版本，不返回签名私钥；未知键不能从未受信来源自动接受 |

失效流是加速传播，不替代高风险在线 CheckAuthorization、浏览器 REST 当前会话校验或 WS 一秒内检查。短期证明和授权缓存仍遵守 DD03.3；快照装载与增量之间的版本水位/竞态需实现规格和测试。

### 14.5 事务、恢复与错误边界

Identity 本地的会话/授权/凭据变更、必要审计、幂等收据和失效 outbox 按用例组合，不等待远程关闭连接再提交。登录/刷新含秘密的幂等重放继续加密并检查响应凭据当前有效性，不能返回已撤销或已轮换失效的结果。

Login/Refresh 的响应丢失按现行同键协议恢复；RotateCredential 涉及新秘密时须单独定义一次性交付及加密重放，不能只返回成功但让客户端永久丢失凭据。Get/Check/Watch 不为每次读创建持久 operation。

沿用既有 INVALID_ARGUMENT、UNAUTHENTICATED、PERMISSION_DENIED、NOT_FOUND、CONFLICT、RATE_LIMITED、TIMEOUT、UPSTREAM_UNAVAILABLE、INTERNAL 等语义并逐方法核对映射；不存在与不可见对外遵守现行策略，不新增可枚举用户的错误细节。

内部调用者可验证服务身份不代表拥有任意主体管理权；角色/范围变更不允许通过未知资源引用或任意 permission 字符串注入新权限。资源引用的登记验证和删除竞态在 DD04 明确，不跨库查表。

### 14.6 定稿范围

DD03.5=B 已由助手按用户授权定稿；字段号、实际 service 文件、精确依赖版本属于实施规格，不再作为待用户确认的架构选择。新接口仍须先补唯一来源再实现，不声称现有接口已经具备。
